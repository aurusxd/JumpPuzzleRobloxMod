## Задачи

Каждая = один вертикальный слайс = один PR. Тесты выводятся из критериев приёмки.

### Стадия 2 — существа

**A1. Инвентарь и выдача.**
Цель: `CreatureService.grant/equip`, `InventorySnapshot`, `CreatureGranted`.
Критерии: выдача пишет экземпляр в профиль с серверным uuid; `equip` отклоняет чужой/несуществующий `instanceId`.
Тесты: контрактный (мусорный payload отклонён), идемпотентность `grant` по ключу награды, путь ошибки при `getProfile == nil`.

**A2. Награды на milestone.**
Цель: `RewardService` слушает `StageCompleted`, `rollFor` по `RewardTable`, `claimedRewards`.
Критерии: на milestone выдаётся ровно одно существо; на не-milestone ничего; повторный `StageCompleted` не даёт дубль.
Тесты: идемпотентность (дважды → одно существо), property-based на веса (частоты сходятся при детерминированном `Rng`), `guaranteedRarityAtLeast`.

**A3. Контент существ.**
Цель: 8 существ в `CreatureDefs`, 8 способностей в `AbilityDefs`, таблицы в `RewardTables`.
Критерии: все `abilityId` существуют, сумма весов > 0, все `modelAsset` заданы.
Тесты: валидатор данных (ссылочная целостность).

**A4. UI существ.**
Цель: экран инвентаря, экипировка, уведомление о награде.
Критерии: только примитивы `ui/primitives`; состояние приходит из `InventorySnapshot`, клиент не пишет в профиль.

### Стадия 3 — арена

**B1. Матч-стейты.**
Цель: `MatchStateMachine` (`Lobby → Countdown → Active → Ended`), портал `ArenaPortal`, `RequestJoinArena/LeaveArena`, `ArenaStateChanged`.
Критерии: игрок не может зайти дважды; выход/смерть возвращает в хаб.
Тесты: таблица переходов, недопустимые переходы отклонены.

**B2. Бой и способности.**
Цель: `ArenaUseAbility`, иерархия `Ability` → `ProjectileAbility`/`AoEAbility`/`DashAbility`/`ShieldAbility`, `DamageCalc`.
Критерии: сервер проверяет кулдаун, жив ли игрок, дистанцию; урон считает только сервер.
Тесты: `DamageCalc` property-based (урон ≥ 0, монотонность по attack), кулдаун не обходится спамом, rate limit работает, отказ вне матча.

**B3. Статы существа в бою.**
Цель: применить `baseStats` экипированного существа (читает сервер из профиля).
Критерии: клиент не может подменить экипированное; смена экипировки во время матча игнорируется.
Тесты: попытка подмены → отказ.

**B4. Итоги матча.**
Цель: обновление `stats.arenaWins/arenaKills/arenaDeaths`, сигнал `MatchEnded`.
Критерии: статы пишутся один раз за матч.
Тесты: идемпотентность записи итогов.

**B5. UI арены.**
Цель: HUD (hp, кулдауны, таймер), экран итогов. Только примитивы, состояние от `ArenaStateChanged`/`ArenaHitConfirmed`.

**B6. Карта арены.**
Цель: зона в Studio, точки спавна, границы. Теги вместо скриптов на деталях.
